# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Teamdesk: rooms, bookings and tasks for a small team. A Bun + Turborepo monorepo: a TanStack Start app on Cloudflare Workers, with D1 as the database. The README files in the root, `apps/web`, `packages/db` and `packages/services` are accurate and worth reading before changing those areas.

## Commands

Run from the repo root.

- `bun install`: install. Its `prepare` step also sets up husky and runs `cf-typegen` (writes the gitignored `apps/web/worker-configuration.d.ts`, which typecheck needs).
- `bun run dev`: applies D1 migrations and `packages/db/seed.sql` to a local SQLite database, then starts the app at http://localhost:3000. No Cloudflare account or env vars needed. Delete `apps/web/.wrangler` for a clean database.
- `bun test`: all tests, against in-memory SQLite.
- `bun run check`: Ultracite (Biome) lint plus `tsc --noEmit` in each package. `bun run fix` formats and applies safe fixes.
- `bun run build`; `bun run deploy` (needs a Cloudflare login and a real D1 id in `apps/web/wrangler.jsonc`).
- `bun run db:apply|db:seed` and their `:remote` variants.

A single test file or name, run inside the package that owns it:

```bash
cd packages/services && bun test src/bookings.test.ts
cd packages/services && bun test -t "daily limit"
```

The pre-commit hook runs `ultracite fix` on staged files and re-stages them, so a commit can change your files and can fail on unfixable lint.

## Architecture

A request flows: route component → tRPC router → service → query functions.

- `apps/web/src/server.ts` is the Worker entry. Hono handles its own routes first, `/api/trpc/*` goes to tRPC, and everything else goes to TanStack Start for SSR and assets.
- `apps/web/src/server/trpc/routers/<area>.ts`: thin. An input schema from the service, then one service call. `context.ts` is the only place that reads `env.DB` and builds the services; a new service needs a line there.
- `packages/services` (`@repo/services/<module>`): business rules and zod validation. A service is a factory taking a drizzle instance. It throws `ServiceError` subclasses, which `init.ts` maps to tRPC and HTTP errors (404, 409, 403, 400). It never reads `env`, bindings or the request. Mutations take the acting member's id first and check permission with `requireMember` or `requireAdmin` (`src/members.ts`).
- `packages/db` (`@repo/db/<table>`): the Drizzle schema, migrations and query functions. Functions take a drizzle `Database`, so the same code runs on D1 in production and on `bun:sqlite` in tests. They return plain JSON shapes and do no validation.
- Client code calls `getTrpc()` from `src/integrations/trpc/client.ts`. In the browser it is an HTTP client; during SSR it runs the router in-process.

There is no sign-in yet, so `userId` in the tRPC context is always null. Pages that change data use a member picker and send the chosen member as `actorId` with every mutation.

## Rules that are easy to break

- **No barrel files.** Each module has its own entry and its own `exports` line in that package's `package.json`. A new table or service needs both the new `src/<name>.ts` and the export line. Use `src/notes.ts` as the template in both packages.
- **Server/browser split.** Browser code imports only `@repo/db/shared` (JSON types and limits). Importing any other `@repo/db` or `@repo/services` entry from a route component pulls drizzle into the browser bundle. Anything the UI needs from the db goes in `packages/db/src/shared.ts`.
- **Migrations.** After editing `packages/db/src/schema.ts`, run `bun run generate` in `packages/db`. Commit `migrations/` including `migrations/meta/`, or the next generate will try to recreate the tables. Wrangler applies the migrations, not drizzle-kit.
- **Tests exercise the real migrations.** `createTestDatabase()` (`@repo/db/testing`) applies them to a fresh in-memory database, and `packages/services/src/fixtures.ts` sets up a small team and two rooms. Tests are `*.test.ts` beside the source.
- **Lint exclusions.** Biome skips `components/ui` and `hooks/use-mobile.ts` (shadcn-generated; `ultracite fix` has corrupted `combobox.tsx` there). Don't hand-edit or reformat them. `apps/web/src/components/bookings/` has PascalCase file names that are exempt from the naming rule; rename them rather than copying the pattern.
- `routeTree.gen.ts` is generated by TanStack Router. Don't edit it by hand; run `bun run generate-routes` in `apps/web` if routes change without the dev server running.
- `wrangler.jsonc` has no `account_id`, so `deploy` and `wrangler whoami` use whichever Cloudflare account is active. Confirm the target before deploying. The demo data is loaded by `db:seed:remote` and is safe to re-run.
